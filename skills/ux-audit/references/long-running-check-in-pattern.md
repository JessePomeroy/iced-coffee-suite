# Bounded long audits

For a comprehensive audit, record a feature inventory, current cursor, completed
evidence, blockers, and next check so work can resume. Use the user's budget or
scope as the stopping boundary. Report uncompleted work; never relabel it clean.

Provide concise progress updates during active work. Do not create a recurring
schedule, background loop, or new task unless requested. Checkpointing does not
require a vendor-specific `/loop` command. Additional passes need a reason such
as a new failure, a correction to verify, or an explicitly requested wider scope.

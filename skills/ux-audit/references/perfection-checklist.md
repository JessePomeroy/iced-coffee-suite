# Component checks

For affected components, select relevant default, focus, active, disabled,
loading, empty, error, and success states. Inspect labels, keyboard operation,
focus return, feedback, reading order, contrast, target size, and text expansion.
A nonexistent state is not applicable, not missing coverage.

Use the declared design system and product task as context. Record actual user
harm for defects. Keep polish opportunities separate and do not require every
component on every page to pass every state during a narrow review.

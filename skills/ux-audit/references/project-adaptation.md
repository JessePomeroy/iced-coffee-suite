# Project adaptation

Inspect the repository's routes, scripts, auth/test fixtures, package manager,
framework versions, and existing browser harness. Prefer a project verification
skill and feature map. Start a server only when needed for the requested audit,
use an isolated supported port/profile, and record the PID and teardown command.

Do not prescribe a particular auth library, ORM, framework, seed command, or
hosting service. Discover how this project provides safe test accounts and data.
Ask for missing access only when it blocks the intended check. Seed or mutate
persistent data only when authorized. A test-looking email address does not make
a real notification harmless.

Inventory features from user-visible routes and controls, then trace source as
needed. Narrow a focused audit to its relevant states; a comprehensive audit
names the included feature set and records unassessed work honestly.
